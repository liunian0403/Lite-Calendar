## 1. 设计目标与使用场景

### 1.1 现状（事实，来自代码）

- 1.1.0 是**全量深色、不可切换**：`src/Theme.cs` 里 19 个静态只读色值（`Theme.Window` / `Surface` / `TextPrimary` / `Accent` …）+ 8 色事件色板，被月/周/日视图、侧栏议程、搜索浮层、编辑对话框、右键菜单、托盘菜单、提醒气泡全部引用。
- 没有任何主题设置项：`AppSettings`（`src/Models.cs:132`）只有 `View`、`DefaultReminderMinutes`、`MinimizeToTray`、`CloseToTray`、`LastExportPath`。
- 标题栏已用 `Theme.ApplyDarkTitleBar`（DWM 属性 20，失败回退 19）固定为深色。
- 界面几乎全部自绘（`MonthView`、`TimeGridView`、`UiButton`、`Segmented`、`DateField`、`FlatCombo`、`FlatCheck`、`MiniMonth`、`SearchList`、`ToastForm`），这使主题切换成本可控；但 `BackColor/ForeColor` 在构造期被写死的原生控件（搜索框、菜单）需要显式重新着色。

### 1.2 为什么要做（用户问题）

1. **白天强光下深色界面看不清**：08:00–18:00 靠窗办公、会议室投屏、户外使用笔记本时，深色背景 + 中灰文字（现 `TextMuted` 仅 3.11:1）反光后几乎无法辨认日期与地点。
2. **夜间白底刺眼**：卧室/夜间使用，浅色界面在低环境光下造成明显眩光，且与用户已设置的 Windows 深色系统割裂。
3. **系统一致性**：Win11 用户大量把系统设为深色/浅色；应用固定深色时，标题栏、任务栏、系统菜单之间观感不一致，像"外来者"。

### 1.3 目标（可验证）

| 目标 | 判据 |
| --- | --- |
| 完整覆盖 | 两套主题下 0 处"深色残留"（浅色模式里没有黑底白字块），逐界面截图抽查通过 |
| 可读性 | 正文/次要/弱化文字对比度 ≥ 4.5:1；状态指示 ≥ 3:1 |
| 即时切换 | 点击菜单到界面完全切换 ≤ 2s（目标 200ms），进程 PID 不变 |
| 偏好保持 | 切换后强杀进程再启动，主题与上次一致，成功率 100%（重复 10 次） |
| 零意外升级 | 1.1.0 用户升级后首次启动仍是深色；全新安装跟随系统 |
| 零新依赖 | 不新增 NuGet/第三方 DLL，仍用系统 `csc` 可编译 |

### 1.4 非目标（明确不做）

- 不跟随 Windows **强调色**（Accent Color 个性化），本版强调色由产品固定。
- 不做按时间/日出日落自动切换（"日落变深色"）—— 会带来"我明明选了浅色为什么变了"的困惑，留待有明确需求再做。
- 不做自定义配色、皮肤包、透明度/亚克力特效。
- 不改字号、行高、圆角、布局、图标；不做切换动画（避免闪烁，且自绘控件动画成本高）。
- 不改事件数据模型、ICS、节假日逻辑、安装包与版本号。

## 3. 三档策略、默认值与入口

### 3.1 三档定义

| 取值 | 菜单文案 | 行为 | 系统主题变化时 |
| --- | --- | --- | --- |
| `system` | 跟随系统 | 启动时读系统深浅色并应用；运行中实时跟随 | **跟随**（≤ 2s 内切换） |
| `light` | 始终浅色 | 永远浅色，与系统无关 | 忽略 |
| `dark` | 始终深色 | 永远深色，与系统无关 | 忽略 |

- 三档互斥，菜单为单选（radio）语义，当前项显示勾选标记（`ToolStripMenuItem.Checked = true`，`CheckOnClick = false`）。
- 取值字符串固定小写：`system` / `light` / `dark`。解析时大小写不敏感、去除首尾空白。

### 3.2 默认值（关键决策）

| 安装情形 | 判据 | 默认档位 | 理由 |
| --- | --- | --- | --- |
| 全新安装 | `%APPDATA%\QingLi\data.xml` **不存在** | `system` | 尊重操作系统设置，是 Windows 应用的通行预期 |
| 从 1.1.0 升级 | `data.xml` 存在，但 `<Settings>` 内**没有** `<Theme>` 元素 | `dark` | 老用户从没见过浅色，升级后突然变白会被当成 bug；保持现状是"零意外" |

**被否掉的备选**：
- *所有情形都默认 `system`*：国内 Windows 默认多为浅色，等于给存量用户强制改外观，发布说明里必须解释，收益为零。否。
- *所有情形都默认 `dark`*：新用户系统是浅色却拿到深色应用，第一印象违和，违背"跟随系统"的行业惯例。否。

**实现提示（阶段 2）**：`EventStore.Load()` 里记录"加载前 `data.xml` 是否存在"，`AppSettings.Theme` 默认值给空串 `""` 表示未设置；启动时若为空 → 按上表解析成 `system` 或 `dark`，并在首次保存时写回具体值。这样判据唯一、可测试。

### 3.3 切换入口

**入口 A（主入口）：主窗口「更多」菜单**
- 位置：「更多」`⋯` 菜单（`MainForm.ShowMoreMenu`），在「导入 ICS」「导出 ICS」之后、分隔线之前，插入子菜单「主题」。
- 子项顺序：跟随系统 / 始终浅色 / 始终深色（与文档、帮助文案一致，顺序不可变）。
- 当前项带勾选；点击后菜单关闭、立即应用、写盘。

**入口 B：托盘右键菜单**
- 托盘菜单（`MainForm.BuildTray`）在「今天」之后、分隔线之前插入同一个「主题」子菜单，结构、顺序、勾选状态与入口 A 完全一致（同一份构建代码，不要复制两份逻辑）。
- 原因：主窗口常驻托盘（`CloseToTray` 默认 `true`），用户可能整晚只通过托盘操作。

**入口 C（P2，可选）：快捷键 `Ctrl+Shift+L`**
- 循环顺序 `system → light → dark → system`，状态栏左侧显示 2s 提示「已切换：始终深色」。
- 与现有快捷键（`Ctrl+N`、`Ctrl+F`、`Ctrl+1/2/3`、`T`、方向键、`Enter`、`Esc`）无冲突。
- 不阻塞验收：未实现时不算缺陷，验收标准中标注为可选。

**不做独立设置窗口**：为一个字段新建模态设置页，成本（布局、DPI、键盘焦点、关闭逻辑）远大于收益；菜单入口已覆盖 100% 使用路径。后续如果有第 3 个以上设置项再统一做设置窗口。

### 3.4 生效时机与范围

| 项 | 要求 |
| --- | --- |
| 是否重启 | **不需要**，点击即生效 |
| 目标时延 | ≤ 200ms 完成重绘；实测上限 2s 视为通过 |
| 重绘范围 | 主窗口（顶栏/侧栏/状态栏/月或周或日视图/搜索浮层）、已打开的编辑对话框、已显示的提醒气泡、之后打开的所有菜单与弹窗 |
| 数据影响 | 不重载日程、不丢失未保存的编辑内容、不改变当前选中日期与视图 |
| 会话影响 | 不重启提醒服务，不重置托盘图标，不改变窗口位置与大小 |
| 写盘时机 | 点击后立即 `store.Save()`（不等退出），避免崩溃丢设置 |

### 3.5 切换反馈

- 菜单勾选状态立即更新（含托盘菜单下一次展开时）。
- 状态栏左侧文案追加临时提示 2s：`已切换到「始终深色」`；无状态栏可见时（窗口隐藏）不提示。
- 不弹窗、不提示"需要重启"。

## 4. 配色规范

### 4.1 设计原则

1. **语义令牌，不写死颜色**：所有绘制只能用令牌（`Theme.Window`、`Theme.TextSecondary`…）。禁止在视图代码里出现 `Color.White` / `Color.FromArgb(...)` 之类的字面量——现状已有 6 处 `Color.White`（按钮文字、今天圆圈、勾选对勾、菜单选中文字、提醒按钮），全部改为 `Theme.OnAccent`。
2. **两套值一一对应**：同一令牌在浅/深两套里语义完全一致，形态可不同（例如 `TodayFill` 深色是深蓝灰、浅色是浅蓝）。
3. **派生色用规则而非手调**：现有 `Theme.Mix(a, b, t)`、`Theme.Alpha(c, a)` 保留，但"重要状态色"必须落到显式令牌（如 `DangerSoftBg`），避免 `Mix(Surface, Danger, 0.35)` 在浅色下退化成 2.87:1 的不可读组合（见 4.5）。
4. **颜色不承载唯一信息**：节假日/调休同时有「休」「班」文字徽标，周末同时依赖列位置与文字；色弱用户仍可分辨。
5. **对比度硬约束**：正文 ≥ 4.5:1，UI 组件/图形 ≥ 3:1（WCAG 2.1 AA / 1.4.11）。

## 5. 持久化

### 5.1 字段

| 项 | 值 |
| --- | --- |
| 位置 | `%APPDATA%\QingLi\data.xml` → `QingLiData/Settings` |
| 元素名 | `Theme` |
| 类型 | `string`（`AppSettings.Theme`） |
| 合法值 | `system`、`light`、`dark`（小写；读取时忽略大小写与首尾空白） |
| 缺省 | 字段为空串 `""` = 未设置，由启动逻辑解析为 `system` 或 `dark`（见 3.2） |
| 写入时机 | 切换主题时立即保存；退出时随现有保存逻辑再写一次 |

```xml
<QingLiData>
  <Version>1</Version>
  <Settings>
    <View>0</View>
    <DefaultReminderMinutes>10</DefaultReminderMinutes>
    <MinimizeToTray>true</MinimizeToTray>
    <CloseToTray>true</CloseToTray>
    <LastExportPath />
    <Theme>dark</Theme>
  </Settings>
  <Events>...</Events>
</QingLiData>
```

### 5.2 回退矩阵

| 情形 | 表现 | 是否提示用户 |
| --- | --- | --- |
| `data.xml` 不存在（全新安装） | `system` | 否 |
| `data.xml` 存在、无 `<Theme>`（1.1.0 升级） | `dark` | 否 |
| `<Theme>` 为空 / 仅空白 | `system` | 否 |
| `<Theme>` 非法（如 `blue`、`1`、`DarkMode`） | `system` | 否（下次保存写回合法值） |
| 语义大小写混合（`Dark`、`SYSTEM`） | 按对应值生效 | 否 |
| `data.xml` 整体解析失败 | 沿用现有逻辑：备份为 `data.xml.corrupt-yyyyMMddHHmmss`，数据重置；主题 `system` | 否（现有行为，不新增弹窗） |
| 无权限写文件 | 主题仅本次会话生效，重启回到已存值 | 否 |
| 同一文件并发写入 | 沿用现有 `tmp` + `File.Replace` + `.bak` 逻辑，不额外加锁 | 否 |

设计原则：**主题读取永不阻断启动，永不弹窗**。主题是偏好，不是数据。

### 5.3 前后兼容

- 新版本读旧文件：XML 反序列化天然兼容缺字段（字段保持默认空串）。
- 旧版本（1.1.0）读新文件：`XmlSerializer` 默认忽略未知元素 `<Theme>`，**不会崩溃**，日程正常可读。
- 旧版本保存后 `<Theme>` 元素被丢弃：再次升级回新版本时按"升级情形"判定为 `dark`。这是可接受的已知回退（用户回到与 1.1.0 一致的深色），需在 README「已知限制」中写明。
- 不改 `Version` 字段（仍为 1），因为新增字段不影响旧解析。

## 6. 跟随系统（实时）

### 6.1 系统深浅色判定

| 项 | 规范 |
| --- | --- |
| 数据源 | `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize` → `AppsUseLightTheme`（DWORD） |
| 取值 | `1` = 浅色；`0` = 深色 |
| 键/值缺失（Win7、精简系统、策略锁定） | 视为**浅色** |
| 读取失败（异常/权限） | 视为浅色，静默降级，不弹窗 |
| 读取时机 | 启动时（主题解析阶段）；运行中每次收到系统主题广播时 |

只读 `AppsUseLightTheme`（应用主题），**不读** `SystemUsesLightTheme`（任务栏/开始菜单），两者可独立。

### 6.2 实时响应

| 项 | 规范 |
| --- | --- |
| 触发消息 | `WM_SETTINGCHANGE`（`0x001A`），`lParam` 指向 `"ImmersiveColorSet"` 时才是主题变更 |
| 监听位置 | `MainForm.WndProc`（唯一监听点，避免多窗口重复处理） |
| 节流 | 收到消息后 500ms 去抖（连续多条只处理一次，避免一次系统切换触发多次重绘） |
| 生效条件 | 仅当当前档位为 `system`；`light`/`dark` 直接忽略 |
| 处理动作 | 重读注册表 → 若与当前生效值不同 → 切换调色板 → 广播 `Theme.Changed` → 所有窗口重设原生控件颜色 + `Invalidate(true)` → 重新应用标题栏 |
| 时延 | ≤ 2s（含 500ms 去抖） |
| 切回「跟随系统」 | 立即重读一次并应用，不等系统广播 |
| 隐藏到托盘时 | 主窗口仍存在（`Hide()`，非销毁），仍会收到广播，主题照常跟随；下次显示即为新主题 |

### 6.3 状态机

```
启动 → 读配置 Theme
   ├─ light/dark → 应用固定调色板，忽略系统广播
   └─ system → 读 AppsUseLightTheme → 应用 → 监听广播
                └─ 广播(ImmersiveColorSet) → 去抖 500ms → 重读 → 变化则应用
```

### 6.4 多窗口一致性

切换调色板后必须同步刷新的窗口（阶段 2 逐个确认）：

| 窗口 | 处理 |
| --- | --- |
| `MainForm` | 自身重绘；标题栏 DWM 重新设置；`_search` 等原生控件重设 `BackColor/ForeColor` |
| `EventDialog`（模态） | 订阅 `Theme.Changed`，重设 `BackColor/ForeColor` 与自绘控件，`Invalidate(true)`；输入内容保留 |
| `PopupForm`（日期选择弹层）、`MiniMonth` | 自绘，随重绘读取新令牌 |
| `ToastForm`（提醒气泡） | 已显示的立即 `Invalidate()`；之后新建的天然使用新令牌 |
| 所有 `ContextMenuStrip`（主菜单/托盘菜单/右键菜单） | 菜单项在 `Theme.Changed` 时重设 `BackColor/ForeColor`；渲染器改为读令牌（现 `DarkMenuRenderer`/`DarkColorTable` 改名 `ThemeMenuRenderer`/`ThemeColorTable`，色值不再写死 `Theme.AccentFill` 之外） |
| 系统 `MessageBox` | **不处理**（见 7.4） |

### 6.5 失败与边界

- 注册表读取抛异常 → 捕获，按浅色处理，写 `QingLi-crash.log`？**不写**，仅静默。
- 系统主题切换瞬间打开菜单/弹窗：允许菜单被关闭或残留一帧旧色，但不得崩溃、不得白屏；重复 3 次仍正常即通过。
- 远程桌面/会话切换、显示器热插拔引起的 `WM_SETTINGCHANGE` 不得误切换（`lParam` 判定必须严格）。

## 7. 标题栏、托盘与提醒弹窗

### 7.1 标题栏（WinForms 原生 + DWM）

| 项 | 规范 |
| --- | --- |
| 方案 | 继续使用 DWM 属性 `DWMWA_USE_IMMERSIVE_DARK_MODE`：深色写 `1`，**浅色写 `0`**（现在只写 1，切回浅色必须显式清零，否则标题栏留着深色） |
| 属性号 | 先 `20`（Win10 1809+/Win11），失败回退 `19`（Win10 早期） |
| 调用时机 | 每个带标题栏的窗口 `OnHandleCreated` + 每次主题切换后 |
| Win11 圆角 | 沿用 `DWMWA_WINDOW_CORNER_PREFERENCE = 2`（圆角）不变 |
| 不支持的系统（Win7 / 关闭 DWM） | 属性调用失败静默忽略：客户区按主题绘制，标题栏保持系统浅色。**列为已知限制**，不为此自绘标题栏 |
| 不自绘的理由 | 自绘标题栏要接管命中测试、最大化/还原、Aero Snap、DPI 缩放、触控，回归风险远高于收益；本项目零第三方依赖、C# 5，自绘成本不可控 |
| 深色标题栏下的窗口按钮 | 由 Windows 绘制，随属性自动变浅色图标，不做额外处理；不做自定义按钮颜色（`DWMWA_CAPTION_COLOR` 仅 Win11 22000+ 可用，且会让标题栏与应用主色不一致，不用） |

### 7.2 托盘

| 项 | 规范 |
| --- | --- |
| 托盘图标 | **不变**（彩色应用图标）。任务栏/托盘区绝大多数为深色底，现有彩色图标可辨；不新增第二套图标，避免安装包资源变动 |

| 双击 | 恢复主窗口，行为不变 |

### 7.3 提醒气泡（`ToastForm`）

## 8. 兼容与降级

### 8.1 旧版本配置（1.1.0 → 1.2.0）

- 现有 `data.xml` 无 `Theme`：判为升级，默认 `dark`（3.2），首次保存写入 `<Theme>dark</Theme>`。
- 事件、视图、提醒、导出路径等字段一律不动。

### 8.2 旧安装包升级

- Inno Setup 覆盖安装只替换 `%LOCALAPPDATA%\Programs\QingLi` 下的程序文件，不动 `%APPDATA%\QingLi`，因此主题偏好与日程自然保留。
- 安装包类型、签名状态（未签名）、SmartScreen 提示均不变。

### 8.3 降级回 1.1.0

- 1.1.0 忽略 `<Theme>`，启动仍是深色，日程可读。
- 1.1.0 保存后 `<Theme>` 丢失；再升回 1.2.0 时按升级情形 → 深色（与降级前一致）。已知限制，写入 README。

### 8.4 数据损坏

- 沿用现有 `data.xml.corrupt-*` 备份 + 重置逻辑；主题回退 `system`，不阻塞启动。
- 主题读取不得因为 `Settings` 为 `null` 而抛空引用（现有代码已重建 `AppSettings`，需保持）。

### 8.5 高 DPI（125% / 150%）

| 项 | 要求 |
| --- | --- |
| DPI 模式 | 保持现有 `system` DPI 感知（`app.manifest`），本轮不改 Per-Monitor V2 |
| 缩放来源 | `Theme.Scale`（启动时按主屏 DPI 计算），布局尺寸 `Theme.S()` 全部随之缩放；颜色与 DPI 无关，**不得**因缩放改变色值 |
| 文字可读性 | 125%/150% 下月/周/日视图、编辑对话框文字不截断、不重叠；「休」「班」徽标单字完整显示（不得出现省略号） |
| 边框 | 保持 1 物理像素（绘制用 `1f`），在 150% 下仍可见；不随缩放变 2px（会显笨重） |
| 多显示器 | 混合 DPI 拖到另一屏时系统位图拉伸导致模糊，属现有已知限制（README 已记录），本轮不修，也不因主题而恶化 |
| 修改缩放 | 需重启应用生效（现有行为），在 README 已知限制中保持说明 |

## 附录 A：对比度自测脚本（测试用，非产品代码）

```powershell
function Lum([string]$hex) {
  $hex = $hex.TrimStart('#')
  $c = @(0,2,4) | ForEach-Object {
    $v = [Convert]::ToInt32($hex.Substring($_,2),16) / 255.0
    if ($v -le 0.03928) { $v / 12.92 } else { [Math]::Pow(($v + 0.055)/1.055, 2.4) }
  }
  0.2126*$c[0] + 0.7152*$c[1] + 0.0722*$c[2]
}
function CR([string]$fg, [string]$bg) {
  $a = Lum $fg; $b = Lum $bg
  if ($a -lt $b) { $t = $a; $a = $b; $b = $t }
  [Math]::Round((($a + 0.05) / ($b + 0.05)), 2)
}
CR '#9494A1' '#232328'   # 深色 弱化文字/卡片 → 5.22
CR '#9B9BA8' '#2C2C32'   # 深色 周末/悬停底 → 5.05
CR '#C42B1C' '#FBE9E6'   # 浅色 节假日/休徽标底 → 4.83
```

## 附录 B：术语

| 术语 | 含义 |

| 反色文字 | 压在强调色填充上的白字（`OnAccent`） |
| 升级情形 | `data.xml` 已存在但没有 `<Theme>` 元素 |
| 实时跟随 | 系统主题变化后应用无需重启自动同步 |
